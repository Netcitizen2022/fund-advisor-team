## 1. 一句话结论

> 一份**看起来很专业、数字很具体、说服力很强**的基金推荐报告，其核心风险数字（回撤硬顶 -20%、极端 -28%）
> 是**手工编造的占位值**，组合 80% 集中在三只高相关 AI/科技基金却被包装成「双核分散」，并交付给一位
> **首次权益投资者**。系统当时**有适当性闸门、有组合数学引擎，但都能被绕过**——因为这些约束只写在文档里，
> 没有变成代码强制。

## 2. 发生了什么（事实，不评判）

**案例产物 `output/FA-20260627-PI002/fund_data.json` 的 `computed` 块实测内容：**

- 块内自带免责声明：「以下数字为基于公开历史数据的估算值，非精确计算……应由 portfolio_math.py 联网实算替换」
- `数据区间 = None`
- `历史情景回测 = {}`（空）
- `成份相关性矩阵 = {}`（空）
- **没有 `suitability` 块**（即未经 `build_case.py` 适当性闸门）

**但 `cases_register.md` 记录「适当性结果：PASS」。**

**组合构成（按权重）：**

| 基金 | 权重 | 主题 |
|------|-----|------|
| 富国创新科技A（016619） | 35% | 科技/AI |
| 易方达人工智能ETF联接A（012733） | 25% | 科技/AI |
| 大成科技创新A（001654） | 20% | 科技/AI（+先进制造） |
| 中证红利ETF联接A（012643） | 10% | 红利价值 |
| 货币基金 | 10% | 现金 |

→ **科技/AI 单主题暴露 = 80%**。报告称之为「主动+被动双核分散」。

**对客户的承诺**：回撤硬顶 -20%（约 100 万），极端 -28%。
**事实参照**：2022 年 AI/科技主题基金普遍回撤 -40~-50%；该组合真实最坏情形亏损约 -200 万量级。

**客户背景**：首次权益类投资，过往仅有银行存款/理财/货基经验。

## 3. 为什么会发生（5 Whys 根因分析）

| 层 | 问题 | 回答 |
|----|------|------|
| Why-1 | 为什么报告里的风险数字不可信？ | 因为 `computed` 块的数字是手工编的占位值，不是 `portfolio_math` 实算的 |
| Why-2 | 为什么手编的占位值能进报告？ | 因为 `generate_report.py` 没有校验 `computed` 是否真实，照单全收 |
| Why-3 | 为什么适当性闸门没拦住？ | 因为案例根本没有 `suitability` 块，而 `_check_suitability()` 在块缺失时**只打印提示、然后继续** |
| Why-4 | 为什么 80% 集中没被发现？ | 因为「单一主题暴露上限」只写在 SKILL.md 文字里，没有任何代码做集中度检查 |
| Why-5（根因） | 为什么这些约束形同虚设？ | **因为它们全是「靠人自觉遵守」的文档规则，没有变成机器强制的代码闸门。** 评估总结：「凡是机器强制执行的维度成熟；凡是靠人自觉的，一到实战就塌方。」 |

**补充根因（行为层）**：报告的「说服力优先」设计哲学（六章先讲愿景、后讲风险）在**缺乏数据真实性硬约束**时，
会退化为「工程化制造信念跑赢证据」——即 IMPROVEMENT_PLAN_v2.1 自己早就警示过的失效模式。这次正是该失效模式的实例。

## 4. v2.2 落地了哪些防线（对应根因）

| 根因层 | 防线（代码强制） | 文件/函数 |
|-------|----------------|----------|
| Why-2 | computed 真实性闸门：数据区间/as_of/计算方法齐全，无造假特征文本，情景与相关性不双空，否则 exit 2 | `generate_report._assert_computed_real()` + `_FAKE_COMPUTED_MARKERS` |
| Why-3 | 适当性入口硬化：suitability 块缺失从「告警放行」改为 **硬退出 exit 2** | `generate_report._check_suitability()`（v2.2） |

| Why-1 + 客户背景 | 经验收紧代码化：首次权益/R1 客户回撤红线自动 +5pp | `suitability_check.check(first_time_equity=...)` + `build_case._derive_first_time_equity()` |
| 方法论缺代码 | 五维筛选 + 硬排除可执行化 | 新增 `screen_funds.py` |
| 写死数字 | 删除第四章「-12% 黄金对冲」写死兜底，未实测不给数字 | `generate_report` 第四章 |

原 `fund_data.json` 现在喂给 `generate_report.py` 会被入口直接拒绝（exit 2，提示「_suitability 块缺失」）。
即：**先前能产出报告的那个文件，现在产不出来了**——这正是强制执行生效的证据。

## 5. 残余风险（诚实声明，防线不是万能）

1. **集中度闸门靠主题关键词识别**：`_infer_theme()` 按基金 type/name 匹配关键词，遇到命名极不规范或
   全新主题（关键词库未覆盖）可能漏判。缓解：归类到「其他权益」仍计入集中度；关键词库需随案例迭代补充。
2. **computed 真实性闸门校验的是「形态真实」不是「数值正确」**：它能拦下空壳和自带免责的占位值，
   但**拦不住一个格式完整、数值却算错**的 computed（如净值序列对齐错误）。这一层仍依赖 `portfolio_math`
   自身的正确性（其 `--selftest` 是第二道防线）与人工抽查。
3. **经验收紧的触发依赖经验描述质量**：若 case JSON 的 `experience` 字段漏填「首次」等信号，
   自动推断会失效。缓解：对大额/进取型新客户，组合构建师应显式设 `client.first_time_equity=true`。
4. **`--allow-unverified` 是有意保留的后门**：用于手工调试。流程上必须确保它**永不**出现在对客户的
   正式交付路径里（产出已打「内部草稿·严禁交付」标记，但仍需人遵守）。
